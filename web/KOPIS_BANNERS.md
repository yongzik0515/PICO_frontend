# 홈페이지 실제 공연 배너 연결 — 2026-10-29

## 화면과 API
- 고정 가상 공연 5건을 제거하고 `GET /api/performances/rankings?size=5`로 최근 7일 KOPIS 집계 상위 5건을 받습니다. 예매처별 순위가 아닙니다.
- 공연명·포스터·공연 기간·공연장을 기존 티켓 캐러셀에 표시합니다. 홈 하단의 긴 집계 설명은 표시하지 않고 상세 모달의 출처 표시는 유지합니다.
- KOPIS에는 예매 오픈 시각이 없으므로 기존 TICKET OPEN/D-day/오픈 중 대신 KOPIS 순위를 표시합니다.
- 가운데 카드 클릭 → `GET /api/performances/{kopisId}` 상세 모달 → KOPIS가 제공한 예매처 링크를 새 탭에서 엽니다. 링크가 없으면 없다고 안내하며 임의 URL을 만들지 않습니다.
- HTTP(S) 외 링크와 사용자정보 포함 URL은 제외하고 외부 링크에 noopener/noreferrer를 적용합니다. KOPIS HTTP 포스터 URL은 HTTPS로 전환합니다.
- 로딩·실패/재시도·빈 목록·포스터 실패를 처리하며 실패 시 가상 공연으로 대체하지 않습니다. 실제 포스터가 없는 경우 배경만 표시됩니다.

## 설정/실행
- 프론트에 KOPIS 키를 넣지 않습니다. 백엔드 KOPIS_SERVICE_KEY를 사용합니다.
- 개발 서버의 API_PROXY_TARGET을 실행 중인 백엔드로 지정하거나, 기존 설정의 로컬 백엔드를 실행합니다. 배포 환경은 기존 VITE_API_BASE_URL/동일 출처 API 라우팅을 사용합니다.
- 이번 확인에서 로컬 localhost:8080은 실행 중이 아니며 로컬 .env의 KOPIS 키도 비어 있었습니다. 운영 https://pico-kr.app 의 공개 순위/상세 API는 실제 데이터로 정상 응답했습니다.
- 로컬 코드 수정만으로 배포 홈페이지가 바뀌지 않습니다. 프론트 변경 배포가 별도로 필요합니다. 배너 변경은 별도 브랜치/PR로 전달하며 이 작업에서 직접 운영 배포하지 않습니다.

## 검증
- `npm run build`: TypeScript/Vite 빌드 통과(큰 JS 번들 경고 존재).
- `npm run lint`: 오류 없이 완료, 다른 기존 파일 경고 존재. 이번 변경 파일에는 lint 경고 없음.
- `node scripts/test-kopis-banners.mjs`: 실제 변환 함수를 대상으로 정상 매핑, 잘못된 ID 제외, HTTP 포스터 HTTPS 전환, 위험 URL 차단, 빈 결과, 실패 전파, 상세 경로, AbortSignal 전달 검증.
- 공개 운영 순위 API 5건/상세 1건, KOPIS HTTPS 포스터 HEAD 200 확인. 실제 사용자 거래/예매 실행 없음.
- 시각적 브라우저 QA는 미실시. 백엔드 코드/API 명세/DB는 변경하지 않았습니다.

## 배너 UI 추가 수정
- 홈 배너 아래 집계기간·집계대상·긴 설명·출처 문단 제거. 상세 모달은 변경하지 않음.
- 눈에 보이는 화살표/원형 버튼 없이 티켓 양끝에 투명 클릭 영역 배치. 키보드 포커스는 표시하고, 1건일 때는 숨김.
- 버튼은 기존 이동 함수를 사용하며 무한 루프 경계 보정 중 중복 클릭 방지. 기존 드래그·자동 넘김·상세 클릭·API·다른 기능은 유지.
