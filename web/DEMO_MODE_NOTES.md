# 데모 모드(dev) 이슈 정리 — 메인 합칠 때 점검용

결제(PG)·본인인증 등이 백엔드에 아직 연결되지 않아, 화면 흐름은 **개발 서버 + 데모 모드**로 확인하고 있다.
이 문서는 그 과정에서 **데모 모드라서 생긴 문제**와, **데모 모드 때문에 앱 코드에 들어간 부분**을 모아 둔 것이다.
메인과 합치거나 실제 백엔드에 붙이기 전에 아래 [점검 목록](#5-합치기-전-점검-목록)을 확인한다.

## 1. 데모 모드 요약

| 항목 | 내용 |
|---|---|
| 켜기/끄기 | 주소에 `?demo=1`(켜짐, 저장됨) / `?demo=0`(꺼짐). 화면 오른쪽 아래 배지의 **데모 초기화**로 진행 상태를 처음으로 되돌림 |
| 동작 범위 | `import.meta.env.DEV`(=`npm run dev`)에서만 설치됨. 빌드 결과물에는 영향 없음 |
| 코드 위치 | `src/demo/demoMode.ts`(가짜 응답), `src/main.tsx`의 `installDemoMode()` 호출, `vite.config.ts`의 `demoState()` 플러그인 |
| 상태 저장 | dev 서버 메모리(`/__demo/state`). 이용자·도우미를 다른 브라우저로 열어도 같은 상태를 봄. 서버에 못 붙으면 localStorage로 대신함 |
| 파일 저장 | dev 서버 메모리(`/__demo/file/{key}`). 증빙 사진을 실제로 보여 주려고 추가함 |
| 주의 | **dev 서버를 재시작하면(또는 `vite.config.ts`를 고치면 자동 재시작) 진행 상태와 올린 파일이 모두 사라짐** |

데모 모드가 가로채는 요청(나머지는 실제 백엔드로 감):

- 결제: `POST /api/agreements/{id}/safe-payment`, `GET /api/payments/{id}/virtual-account`, `POST /api/payments/{id}/confirm`, `POST /api/payments/{id}/cancel`, `GET /api/payments/{id}/refunds`
- 착수·결과: `POST /api/requests/{id}/start`, `POST .../result`, `POST .../result/confirm`, `POST .../dispute/withdraw`, `GET·POST .../dispute/messages`, `GET .../mediation`, `GET .../partial-settlement`
- 증빙: `POST·GET .../attempt-evidences`, `POST·GET .../result/evidence`, `POST /api/attempt-evidences/{id}/approve|reject`, `POST /api/(files|evidence-files)/upload-url`
- 후기: `POST·GET·DELETE /api/requests/{id}/review`
- 도우미 신청: `GET /api/me/identity`, `POST /api/me/identity/(verification-session|verify)`, `GET·PUT /api/me/payout-account`, `PUT .../profiles/{id}/business`, `POST .../profiles/{id}/submit`, `GET /api/me/agent/profiles`
- 조회 덮어쓰기(실제 응답을 받아 단계만 바꿈): `GET /api/requests`(목록), `GET /api/requests/{id}`, `GET /api/requests/{id}/agreements`

## 2. 데모 모드라서 생겼던 문제 (2026-10-03)

모두 **데모 모드 코드만 고쳤고**, 실제 백엔드에 붙이면 생기지 않는 문제다.

| 증상 | 원인 | 고친 내용 |
|---|---|---|
| 예매 결과 카드에 결과 설명이 안 나옴("등록된 결과 설명이 없어요") | 결과 등록을 가로채 결과(성공·실패)만 저장하고 설명·확보 내용은 버림 | 결과 설명(`agentResultNote`)·확보 내용(`agentActualOutcomeDescription`)도 저장해 상세에 내려 줌 |
| 후기를 썼는데 '후기 작성' 버튼이 다시 나옴 | 후기 작성을 가로채 성공만 답하고 저장 안 함. 상세는 실제 서버에서 후기를 찾음 | 후기 내용 저장·조회·삭제를 데모가 처리. 같은 거래 재작성은 409, 삭제 후에도 재작성 불가 |
| 결과 등록 때 올린 사진이 안 보임 | 업로드 주소가 가짜(`pico-demo.invalid`)라 파일을 버림. 증빙 목록도 저장 안 함 | dev 서버가 파일을 받아 보관하고, 시도·결과 증빙 목록과 시도 증빙 승인·반려를 데모가 처리 |
| 내 활동 목록이 '안전거래 결제 대기'로 나옴(상세는 결과 확인 단계) | 데모가 상세 조회만 단계를 바꾸고 목록(`GET /api/requests`)은 실제 응답 그대로 씀 | 목록에서도 데모로 진행한 요청의 단계를 상세와 같게 바꿈 |
| 분쟁 소명에 첨부한 파일이 사라짐 | 소명 제출을 가로채 첨부를 항상 빈 목록(`attachments: []`)으로 저장 | 업로드 때 기록한 파일 정보로 첨부 목록을 만들어 저장 |
| 도우미 신청을 제출해도 현황이 '신청서를 작성하고 있어요'로 나옴 | 심사 신청을 가로채 '심사 중'이라고 답만 하고 저장하지 않음(현황은 저장된 상태로 판단) | 제출하면 데모 상태를 '심사 중'으로 저장 |
| 가상계좌 입금액이 항상 10,000원 | 가짜 계좌 응답에 금액이 고정돼 있었음 | 금액을 빼서 화면이 선택한 항목의 합계를 보여 주게 함 |
| (2026-10-05) 휴대폰 폭(767px 이하)에서 데모 배지가 하단 탭바와 도우미 프로필의 '이 도우미에게 요청하기'(하단 고정 바)를 가림 | 배지가 화면 아래에 고정돼 있는데, 같은 자리에 하단 탭바(66px)와 요청 바(78px)를 새로 둠 | 767px 이하면 배지를 헤더 바로 아래 오른쪽에 두고 '● 데모 ▸'로 접어 둠(누르면 펼침). 페이지를 연 시점의 폭으로 정해지므로 창 크기를 바꾸면 새로고침해야 반영됨 |

### 데모에서 실제와 다르게 보이거나 볼 수 없는 것

- **운영팀 결과 조정안**: 데모는 조정안 조회를 항상 '없음'으로 답한다(`GET .../mediation` → `NONE`). 분쟁 중 조정안 카드(수락·거부)와 부분성공 정산의 조정안은 데모에서 볼 수 없다. 실제 백엔드에서 관리자 화면으로 조정안을 보내 확인해야 한다.
- **운영팀 추가 자료 요청**: 데모 상태에 질문을 넣으면 소명 카드에는 보이지만 알림은 만들어지지 않는다(알림은 실제 서버에서만 옴). 또 데모는 소명 기록을 이용자·도우미가 함께 써서, 받는 사람을 지정한 질문도 양쪽에 다 보인다.
- **도우미 심사 결과**: 배지의 '도우미 승인'·'보완 요청'·'반려'로 바꿀 수 있다. '보완 요청'은 실제 백엔드에 없는 상태다(USER_FLOW.md 11번). 데모로 승인된 도우미의 '활동 중'(공개 설정)은 실제 서버가 승인 전이라 데모가 저장하고 `GET /api/me`에 반영한다.
- **데모 초기화**를 누르면 위처럼 넣어 둔 질문·소명·증빙도 모두 지워진다.

## 3. 데모 모드 때문에 앱 코드에 들어간 부분 (실제 백엔드 지원 필요)

착수비·수고비 항목별 결제는 2026-10-04에 롤백했다. 결제 화면은 명세대로 전액을 한 번에 결제한다(`USER_FLOW.md` 6번).

| 위치 | 내용 | 실제 백엔드에서 |
|---|---|---|
| `src/pages/ApplicationPage.tsx` 경력 인증 | 경력 사례를 1건만 받음. 데모는 심사 신청을 가로채 통과시킴 | 심사 신청 API가 사례 1~3을 모두 요구해 **신청 실패**(`USER_FLOW.md` 9번) |
| `src/pages/CreditsPage.tsx` 매칭권 충전 | 수량을 2~100장으로 직접 입력(데모 모드와 무관하게 실제 서버로 감) | 서버가 10장 묶음만 팔아 **10장이 아닌 수량은 주문 실패**(`USER_FLOW.md` 12번) |

## 4. 데모가 아니라 실제 앱 버그였던 것 (참고)

- **결제 화면 재진입 시 가상계좌를 다시 발급받게 하던 문제**: 요청·합의 응답에 결제 상태(`PENDING`)가 있으면 결제 상세를 따로 불러오지 않는데(`fetchDetail`), 결제 화면은 결제 상세에서만 기존 주문을 찾았다. 요청·합의의 결제 상태와 번호에서도 찾도록 고쳤다(`PaymentPage.tsx`). 실제 백엔드에서도 필요한 수정이다.

## 5. 합치기 전 점검 목록

- [ ] `?demo=0`으로 끄고 실제 백엔드로 결제 → 착수 → 결과 등록 → 결과 확인 → 후기까지 한 번 돌려 본다.
- [ ] 실제 업로드 주소(S3 등)로 올린 결과·시도 증빙 사진이 상세의 예매 결과 카드에 보이는지 확인한다(`url` 필드 사용).
- [ ] **운영팀 결과 조정안**(데모에서 볼 수 없음): 실제 백엔드에서 분쟁 거래에 관리자 화면으로 조정안을 보내고, 이용자·도우미 화면의 조정안 카드(수락·거부, 최대 2회, 3일 기한, 합의 실패 시 보류 안내)를 확인한다. 부분성공 정산의 '운영팀에 넘기기' → 금액 조정안도 같이 확인한다.
- [ ] **운영팀 추가 자료 요청**(데모에서는 알림이 안 옴): 관리자가 '추가 자료 요청'을 보내면 지정한 한쪽에게만 알림이 가고, 알림을 누르면 요청 상세로 이동해 '분쟁 소명·추가 자료'의 빨간 안내와 '답변' 입력란이 보이는지 확인한다.
- [ ] 데모 모드를 지울 때: `src/main.tsx`의 `installDemoMode()` 호출과 import, `src/demo/` 폴더, `vite.config.ts`의 `demoState()` 플러그인(`/__demo/state`, `/__demo/file/`)을 함께 지운다. `pc-refinements.css` 등 화면 코드는 데모와 무관하다.
- [ ] 데모 모드 코드에 남은 옛 업로드 처리(`https://pico-demo.invalid/`)는 지금 쓰이지 않는다. 데모를 계속 쓸 거면 정리한다.
