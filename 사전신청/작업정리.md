# 작업 정리 · 도우미 온보딩(사전 신청) 시안

기간: 2026-10-08 ~ 2026-10-10

## 목표와 조건

- 도우미 대상 마케팅용 사전 이용 페이지예요. "여기를 누르면 돼요" 식으로 사용법을 알려 주고, 마지막에 사전 신청으로 이어져요.
- 실제 서버는 PG사 심사 중이라 쓰지 않아요. 가짜 데이터로 만들고 Vercel에 배포할 예정이에요.
- 범위는 기본 흐름 전부예요. 분쟁(부분 성공·실패·이의 제기)은 "이런 경우가 있다"는 소개만 해요.

## 진행 순서

### 1. 1차 시안 (캔버스 '1차 시안' 페이지)

- 시작 화면(장 고르기)을 PC와 휴대폰으로 만들었어요.
- 같은 단계를 두 가지로 비교했어요(PC·휴대폰).
  - A안 딤: 누를 곳 말고는 어둡게
  - B안 강조: 다 보이게 두고 누를 곳만 강조
- 장 마침 화면과 이의 제기 사례 페이지도 만들었어요.

### 2. 2차 방향 결정

- 따로 시작 화면을 두지 않고 메인에서 바로 시작해요.
- 휴대폰은 B안으로 정했어요. 화면이 어두우면 나중에 실제 화면이 낯설 수 있어서예요.
- 안내 문구는 짧게 써요.
- 함께 해 보기를 마치면, 강조 없이 혼자 해 보는 단계가 이어져요.

### 3. 2차 시안 다듬기

- **메인:** 인사 카드형과 캐릭터형을 비교해 캐릭터형으로 정했고, 캐릭터는 화면을 가리지 않게 작게 줄였어요.
- **메인 소개:** 하나씩 넘기던 방식을 한 번에 보여 주는 방식으로 바꿨어요. 배너·검색·도우미 목록에 라벨을 붙이고 '마이'만 강조해요.
- **흐름:** 요청 수락까지였던 범위를 결과 증빙 제출까지 늘렸어요.
- **말풍선**
  - '요청 수락 · 2/3' 같은 단계 표시와 다음·이전 버튼을 뺐어요.
  - 제목 한 줄과 짧은 보조 문구, 작은 캐릭터 얼굴만 남겼어요.
  - 진행 정도는 헤더 아래 얇은 막대로 보여 줘요(15단계).
- **가림 없애기:** 화면 위에 뜨던 까만 알림을 뺐어요. 말풍선은 강조한 곳 바로 아래 빈자리에 넣어 다른 요소를 가리지 않게 했어요.
- **분쟁 소개:** 부분 성공·실패·이의 제기는 체험 대신 '이런 경우도 있어요' 화면에서 흐름만 소개해요.
- **결과 등록:** 결과를 먼저 고르면 결과마다 다른 화면으로 넘어가요.
- **혼자 해 보기:** 메인부터 결과 등록까지 전 과정을 해요. 칸은 비어 있고 "아무 내용이나 적어도 돼요"라고 안내해요.

### 4. 실제 화면과 맞추기 (`web/src` 화면 코드와 대조)

- **요청 상세 (요청서 페이지 추가)**
  - 실제 순서대로 요청서 13개 항목 → 연락방법 → 진행 상황(6단계) → 버튼을 보여 줘요.
  - 함께 해 보기에서는 요청서를 끝까지 내리면 '요청 수락하기' 단계로 넘어가요.
- **문구:** 다음 단계 문구, 상태 배지, 착수 확인 창, 결과 등록 안내를 실제 문구로 바꿨어요.
- **화면 구성:** 마이페이지, 받은 요청 카드, 최종 조건 작성 칸(실패·환불 처리, 기타 사항, 결과 연락 기한, 수수료 내역)을 실제와 맞췄어요.
- **하단 탭:** 요청과 관련된 화면에서는 실제처럼 '받은 요청'이 켜져요.

### 5. 사전 신청

- 혼자 해 보기를 마치면 '사전 신청하러 가기' 버튼이 나와요.
- 누르면 도우미 신청 화면으로 가요. 혜택 안내와 '사전 신청하고 회원가입하기' 버튼이 있어요.
- 혜택 3개는 아직 예시예요.

## 확인한 방법과 한계

- 보드의 템플릿 값과 태그 짝을 스크립트로 검사했어요(`design/holes.cjs`).
- 가짜 실행으로 화면 이동, 단계, 빈칸 검사를 확인했어요(`design/flow.cjs`).
- 캡처로 화면 모양을 확인하지는 않았어요.
- 실제 앱은 로그인한 화면을 띄울 수 없어서 코드로만 대조했어요.
